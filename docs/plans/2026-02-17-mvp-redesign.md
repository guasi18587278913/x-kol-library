# 推特大佬电子阅览室 - MVP 重新设计方案

**日期**: 2026-02-17
**状态**: 已确认，待开发

---

## 1. 产品定位

### 核心价值主张
为**中国用户**提供无障碍阅读 Twitter 大佬完整内容的平台，无需跳转到 Twitter。

### 目标用户
- 关注 AI、创业、投资、商业等领域的中国专业人士
- 无法或不便访问 Twitter 的用户
- 希望高效浏览优质推文内容的读者

### 产品定位
**"数字图书馆 × 现代杂志"** - 专业、安静、有品质感的阅读体验

---

## 2. 核心功能（MVP 范围）

### ✅ 必须有的功能
1. **完整推文阅读**
   - 显示完整推文内容（非摘要）
   - 中文推文直接展示
   - 英文推文提供中文翻译（使用 Claude API）
   - 图片完整显示
   - 视频提供跳转链接

2. **内容发现**
   - 首页：精选推文 + 类目卡片 + 全部推文时间线
   - 类目浏览：7 大类目（AI、创业、投资、商业、设计、内容、营销）
   - KOL 详情页：展示 KOL 信息 + 推文时间线
   - 全局搜索：搜索 KOL 和推文内容

3. **KOL 展示**
   - **必须显示 KOL 头像**（当前缺失，需补充）
   - 显示 KOL 基本信息（名称、username、简介、粉丝数）
   - 按类目分类

### ❌ 不做的功能（MVP 阶段）
- ❌ 用户登录/注册
- ❌ 用户互动（点赞、评论、收藏）
- ❌ 个性化推荐
- ❌ 社区讨论
- ❌ 移动端优化（PC 端优先）
- ❌ 管理后台（用脚本管理）

### 设计理念
参考 [zengzhang.ai](https://www.zengzhang.ai/) 的极简专业风格，但打造独特的"推特阅览室"体验。

### 配色方案

**主色调：深蓝色系（Twitter Blue）**
- `Primary`: `#1D9BF0` (Twitter Blue)
- `Primary Dark`: `#1A8CD8`

**中性色：灰度系统**
- `Background`: `#FAFAFA` (浅灰背景，护眼)
- `Card`: `#FFFFFF` (纯白卡片)

- `Text Secondary`: `#536471` (辅助文字)

3. **层次清晰** - 明确的视觉层级
4. **专业克制** - 避免过度设计

## 5. 数据策略

### 数据规模
- **初始数据**：164 位 KOL
- **每个 KOL**：抓取最近 50-100 条推文
- **总推文数**：~16,400 条（初始）
- **持续增长**：后续会添加更多 KOL

### 更新频率
- **每天自动更新**：定时任务每天运行，抓取新推文
- **增量更新**：只抓取新发布的推文，避免重复

### 数据处理流程

```
1. 抓取推文 (X MCP 工具)
   ↓
2. 检测语言 (中文 or 英文)
   ↓
3. 如果是英文 → 调用 Claude API 翻译
   ↓
4. 存入数据库 (原文 + 译文)
   ↓
5. 抓取推文图片 URL
   ↓
6. 更新 KOL 头像 (如果缺失)
```

### 翻译方案
- **翻译服务**：Claude API (Anthropic)
- **翻译时机**：抓取时立即翻译
- **存储方式**：
  - `content`: 原文
  - `content_zh`: 中文翻译（如果是英文推文）
  - `language`: 语言标识 (`zh` / `en`)

## 6. 数据库 Schema 更新

### 需要添加/修改的字段

**kols 表**:
```sql
ALTER TABLE kols
  ADD COLUMN IF NOT EXISTS avatar_url TEXT DEFAULT '';
  -- 确保所有 KOL 都有头像
```

**tweets 表**:
```sql
ALTER TABLE tweets
  ADD COLUMN IF NOT EXISTS language VARCHAR(10) DEFAULT 'zh',
  ADD COLUMN IF NOT EXISTS content_zh TEXT DEFAULT '',
  ADD COLUMN IF NOT EXISTS translated_at TIMESTAMPTZ;
  -- language: 原文语言 ('zh' 或 'en')
  -- content_zh: 中文翻译（英文推文才有）
  -- translated_at: 翻译时间
```

## 10. 技术决策和权衡

### 为什么选择独立定时任务服务？
- ✅ Vercel Serverless Functions 有 10 分钟执行时间限制
- ✅ 抓取 16,400 条推文 + 翻译会超时
- ✅ 独立服务可以控制抓取速度，避免 API 限制
- ✅ Railway/Render 提供免费托管

### 为什么选择 Claude API 翻译？
- ✅ 翻译质量优秀，理解上下文能力强
- ✅ 适合社交媒体内容的翻译（保持语气和风格）
- ❌ 成本相对较高，但 MVP 阶段可接受

### 为什么暂不做移动端优化？
- ✅ MVP 阶段快速验证产品价值
- ✅ PC 端体验优先打磨
- ✅ 后续根据用户反馈再优化移动端

### 为什么不做用户系统？
- ✅ MVP 专注核心阅读体验
- ✅ 避免功能过载，降低开发复杂度
- ✅ 后续根据需求再添加

## 12. 风险和挑战

### 技术风险
1. **Twitter API 限制** - 抓取频率过高可能被限制
   - 缓解措施：控制抓取速度，使用 MCP 工具的限流机制

2. **翻译成本** - Claude API 调用成本
   - 缓解措施：只翻译英文推文，缓存翻译结果

3. **图片加载速度** - 大量图片影响性能
   - 缓解措施：懒加载、CDN、图片压缩

### 产品风险
1. **版权问题** - 展示 Twitter 内容的合法性
   - 缓解措施：标注来源，提供原文链接，非商业用途

2. **内容更新** - KOL 停更或删推
   - 缓解措施：定期检查失效内容，及时清理
